- 文档状态：功能设计稿 / 待实现

- 视频分析：`video_analysis/操作分析.md`
- 适用范围：InspireSpace 无限画布、画布节点拖拽、堆叠管理

## 1. 功能目标

在无限画布上提供一种比“文件夹”更轻、更直接的临时组织方式：用户可以把项目拖到另一个项目上形成堆叠，将更多项目追加进堆叠，展开查看成员，整体移动堆叠，并把单个成员重新拖出。

核心体验必须保持连续：

> 抓起 → 跟手移动 → 目标激活与吸附 → 释放合并 → 成功反馈 → 展开/收拢 → 整体移动 → 单项取出 → 剩余成员补位

任何一次操作都应让用户看清楚“项目从哪里来、进入了哪里、取出后留在了哪里”，不得通过瞬移或突然替换破坏空间关系。

## 2. 与现有功能的关系

### 2.1 堆叠与文件夹必须并存

| 能力 | 堆叠 Stack | 文件夹 Folder |
|---|---|---|
| 用途 | 画布上的快速归拢、临时分类、视觉整理 | 持久容器与内容归档 |
| 数据关系 | 成员通过 `stackId` 关联 | 子项通过 `parentId` 关联 |
| 打开方式 | 原地展开为画布网格 | 打开现有 `FolderFocus` 模态面板 |
| 画布占位 | 紧凑态占一个画布位置 | 文件夹节点占一个画布位置 |
| 拖出成员 | 在画布原地展开后直接拖出 | 继续沿用文件夹内的管理逻辑 |
| 是否改变父子关系 | 否 | 是 |

规则：

1. 拖到普通画布项目上，创建堆叠。
2. 拖到已有堆叠上，加入该堆叠。
3. 拖到文件夹节点上，仍执行“移入文件夹”，不得被堆叠逻辑拦截。
4. 文件夹自身可以作为普通项目加入堆叠，但当文件夹是当前投放目标时，文件夹投放优先级高于创建堆叠。
5. 堆叠展开不是 `FolderFocus`，不打开遮罩、不离开当前画布上下文。

### 2.2 与现有实现的衔接

现有项目已经具备：

- `CanvasNode.stackId`：表示节点所属堆叠；
- `stackSelected()` / `unstack()`：基础成堆和拆堆能力；
- 拖动堆叠顶层节点时整组移动；
- 拖动堆叠成员到空白区域后解除 `stackId`；
- 撤销/重做和本地持久化。

本功能不是另起一套分组系统，而是在上述能力上增加：拖放创建、目标反馈、紧凑外观、原地展开、成员提取、局部补位和完整动画状态。

## 3. 术语

- **画布项目 / 节点**：便签、笔记、图片、视频、网页卡片、文档、插件、文件夹等可移动对象。
- **堆叠**：两个及以上根级画布项目组成的轻量集合。
- **成员**：属于某一堆叠的画布项目。
- **锚点**：堆叠在画布上的逻辑位置，也是展开/收拢动画的来源和归宿。
- **紧凑态**：成员重叠，仅占一个画布位置的状态。
- **展开态**：成员从锚点展开为规则网格，可单独操作的状态。
- **堆叠外壳**：紧凑态的顶层卡片、标题区、数量标签及可拖拽区域。
- **激活区**：拖入后允许创建或追加堆叠的有效目标区域。
- **提取**：从展开堆叠中拖出一个成员，使其恢复为独立画布项目。
- **局部重排**：只移动本次操作影响范围内的项目，避免全画布跳动。

## 4. 功能范围

### 4.1 本期包含

1. 单项目拖到单项目上创建堆叠。
2. 单项目拖到已有堆叠上追加成员。
3. 堆叠紧凑态和成员数量显示。
4. 悬停、点击或键盘操作展开堆叠。
5. 离开交互区域、按 `Esc` 或点击空白处收拢堆叠。
6. 从堆叠外壳拖动整个堆叠。
7. 从展开态拖出单个成员。
8. 提取取消、成员补位、成员数更新和单成员自动解散。
9. 创建、追加、提取、移动、解散均支持一次撤销/重做。
10. 顶部轻量成功提示。
11. 常规动画和“减少动态效果”模式。

### 4.2 本期不包含

1. 堆叠嵌套堆叠。
2. 将一个完整堆叠合并到另一个堆叠。
3. 展开态内手动拖拽排序；本期成员顺序按稳定规则自动维护。
4. 堆叠内搜索、筛选、滚动容器或独立详情页。
5. 多人协作时的堆叠冲突处理。
6. 自动按内容语义推荐堆叠。

## 5. 用户故事

1. 作为用户，我可以把一张卡片拖到另一张卡片上，快速把它们归为一堆。
2. 作为用户，我可以继续把卡片拖到已有堆叠上，不需要先展开或打开面板。
3. 作为用户，我能从数量和层叠边缘判断一个对象是否为堆叠。
4. 作为用户，我可以在原地展开堆叠，并明确看到每个成员从堆叠中展开出来。
5. 作为用户，我可以拖动堆叠外壳，一次移动所有成员。
6. 作为用户，我可以从展开态拿出一个成员，并看到其他成员填补空位。
7. 作为用户，如果误操作，我可以把成员拖回原区域取消提取，或通过撤销恢复。

## 6. 功能需求

### FR-01 拖拽启动

1. 仅主指针按键可发起拖拽；触控使用单指长按/移动语义。
2. 指针按下后进入 `pressed`，累计移动超过 **4 屏幕像素**才进入正式拖拽。
3. 未超过阈值时按普通点击处理，不改变成员关系。
4. 进入拖拽后：
   - 被拖对象提升到当前交互最高层；
   - 阴影增强；
   - 视觉缩放至 `1.015–1.025`；
   - 光标切换为抓取中状态；
   - 原位置保留内部占位信息，但自由画布不显示生硬的空框。
5. 拖动位置必须与指针同步，更新延迟目标为单帧内，不使用会在松手后回到旧坐标的临时合成层。

### FR-02 堆叠目标判定

可作为堆叠目标的对象：

- 不属于文件夹内部的根级普通节点；
- 已存在的紧凑堆叠；
- 不是当前被拖对象，也不是当前整组移动中的成员。

不可作为目标：

- 被拖对象自身；
- 正在编辑、缩放或有模态交互的节点；
- 已被移入文件夹的子节点；
- 另一个完整堆叠（本期不支持堆叠合并）。

激活建议同时满足以下条件：

1. 被拖对象与目标的有效重叠比例达到 **20%**；或指针进入目标中央 **60%** 区域；
2. 条件连续保持 **80–120 ms**，避免高速掠过时误激活；
3. 指针仍在目标方向移动或基本停留，而不是明显离开。

取消激活使用滞回规则：重叠比例降到 **12%** 以下，或离开扩展热区 **80 ms** 后再取消，防止边界抖动。

若同时命中多个目标：

1. 文件夹投放优先；
2. 其次选择指针所在目标；
3. 再按重叠比例从高到低；
4. 最后按视觉层级从高到低。

### FR-03 创建新堆叠

操作：将一个独立项目拖到另一个独立项目上并释放。

释放后按以下顺序执行：

1. 锁定目标，短时间内不再切换投放对象；
2. 被拖项目从当前位置向目标锚点吸附；
3. 目标项目轻微抬升，被拖项目落入其后方或上方层级；
4. 为两个成员分配同一 `stackId`；
5. 生成堆叠锚点和稳定成员顺序；
6. 切换为紧凑态视觉；
7. 释放源项目原占位；
8. 对受到碰撞影响的邻近节点执行局部重排；
9. 顶部显示“已创建堆叠”（英文界面为 `Created a Stack`）。

创建必须作为一个原子历史操作：一次撤销恢复两个项目的原位置和独立状态。

### FR-04 向已有堆叠追加成员

操作：将一个独立项目拖到紧凑堆叠上并释放。

1. 堆叠目标被激活时，数量标签可以临时显示 `N → N+1` 或 `+1`。
2. 释放后，新成员沿当前拖入方向进入锚点，不能瞬间消失。
3. 原有成员只做小幅让位/层边偏移，不全部重新弹跳。
4. 新成员加入稳定成员顺序的末尾，并获得最高成员层级。
5. 数量标签在合并动画中后段更新为新数量。
6. 追加操作显示较弱的“已加入堆叠”提示；连续快速追加时合并为一个提示，不重复堆积。

### FR-05 紧凑态外观

1. 整个堆叠只占一个逻辑画布位置。
2. 顶层成员保持其原卡片视觉，后方最多显示 **2–3 层**错位边缘，避免成员过多导致无限层叠。
3. 后方层边使用小幅位置和角度差：
   - 水平偏移约 `3–7 px`；
   - 垂直偏移约 `3–6 px`；
   - 旋转不超过 `±1.4°`。
4. 数量标签固定关联堆叠，不随某个成员内容消失；显示为“9 项”或仅数字加层叠图标。
5. 可显示堆叠标题；默认名称为“未命名堆叠”，用户后续可重命名。
6. 顶层内容必须仍可识别，但普通点击优先选中堆叠而不是误触顶层卡片内部编辑。
7. 双击或 `Enter` 展开；悬停达到展开延时后也可展开。

### FR-06 展开堆叠

触发方式：

- 指针在紧凑堆叠上稳定悬停 **180–260 ms**；
- 双击堆叠；
- 选中堆叠后按 `Enter` 或 `Space`。

展开规则：

1. 堆叠进入 `stack-expanding` 后不再响应普通画布拖拽，直到主要动画结束。
2. 成员从同一锚点向外展开为规则网格，不使用随机散开。
3. 默认列数：
   - 2–4 项：2 列；
   - 5–9 项：3 列；
   - 10–16 项：4 列；
   - 17 项以上：最多 5 列并继续增加行数。
4. 成员不被强行拉伸成相同尺寸。每列宽度取该列成员最大宽度，每行高度取该行最大高度，槽位间距建议 **20–28 画布像素**。
5. 优先以锚点为网格中心；靠近视口边缘时整体平移展开网格，使至少标题和主要成员留在视口可见区域。
6. 展开后的成员整体层级高于普通画布节点，但低于工具栏、上下文菜单、编辑器和模态窗口。
7. 堆叠标题、数量和外壳句柄保持与网格关联，并提供“拖动整个堆叠”的明确抓取区。
8. 展开坐标属于临时交互布局，不覆盖成员的持久画布位置；只有整体移动或成员提取完成时才提交持久坐标。
9. 展开完成后，成员可以被选中、打开或发起提取。

### FR-07 收拢堆叠

触发条件：

- 指针离开展开网格、堆叠标题和成员之间组成的联合热区；
- 点击堆叠外空白区域；
- 按 `Esc`；
- 打开其他模态交互；
- 当前堆叠失去焦点且没有成员正在拖动。

规则：

1. 指针离开后延迟 **120–180 ms**再收拢；若指针在延迟内返回则取消收拢。
2. 联合热区应覆盖成员外接矩形、成员间隙和约 **24 画布像素**安全边距，不能因指针穿过卡片间隙而闪烁收拢。
3. 成员沿展开路径的反方向回到锚点。
4. 外围成员可以先开始，靠近中心的成员后开始，形成“吸回”层叠感。
5. 收拢比展开略快；完成前保留展开态的交互遮罩，避免下方节点误响应。
6. 收拢完成后恢复紧凑层级和数量标签。

### FR-08 移动整个堆叠

操作入口：

- 紧凑态拖动顶层卡片非交互区域；
- 展开态拖动堆叠标题/外壳句柄。

规则：

1. 进入 `dragging-stack` 后，所有成员保持同一个 `stackId` 和成员顺序。
2. 紧凑态移动时，所有层边作为一个整体跟手移动。
3. 展开态移动时，成员网格整体平移，相对槽位不变。
4. 拖动过程中附近节点可显示轻微避让预览，但不得不断写入历史。
5. 释放后一次性提交锚点和成员持久坐标，并生成一条历史记录。
6. 若释放点造成重叠，只对落点附近节点执行局部碰撞重排；不重排整张无限画布。
7. 整体堆叠不能在一次拖动中直接合并到另一堆叠；命中另一堆叠时按普通画布落点处理，并显示不可合并反馈。

### FR-09 从堆叠中提取成员

前置条件：堆叠已经展开。

1. 用户在具体成员上按下并超过拖拽阈值后进入 `extracting-item`。
2. 被提取成员提升到最高交互层，保持完整卡片外观并跟随指针。
3. 原网格保留一个临时空槽；其他成员在拖动过程中不得立刻跳位。
4. 堆叠数量在拖动期间可显示 `N` 并附带减一预览，但正式数量只能在释放成功后提交。
5. 若释放点位于堆叠联合热区外：
   - 清除该成员的 `stackId`；
   - 将指针释放位置换算为独立节点的持久画布坐标；
   - 成员落下成为独立项目；
   - 堆叠成员数减一；
   - 剩余成员填补空槽；
   - 更新堆叠标题/数量显示；
   - 必要时对附近画布节点做局部避让。
6. 若成员被拖回原空槽或堆叠联合热区内释放：
   - 取消提取；
   - 恢复原成员顺序；
   - 成员沿短路径回到原槽；
   - 不创建历史记录。
7. 若释放到文件夹：成员从堆叠移除并写入目标文件夹的 `parentId`，整个动作作为一条原子历史记录。
8. 若释放到另一个普通独立项目：本期先完成“从原堆叠取出”，不在同一次手势中继续创建新堆叠，避免一次拖放产生难以理解的双重关系变化。

### FR-10 补位与自动解散

1. 成员成功提取后，按稳定成员顺序填补空槽。
2. 补位使用 FLIP 类位移动画，不能先跳到新位置再淡入。
3. 若提取后还剩两个及以上成员，堆叠继续存在。
4. 若只剩一个成员：
   - 自动清除最后成员的 `stackId`；
   - 最后成员落在堆叠锚点；
   - 数量标签和后方层边淡出；
   - 该过程与提取动作属于同一条撤销记录。
5. 空堆叠不得持久化。

### FR-11 局部重排

InspireSpace 是自由布局无限画布，因此局部重排必须遵守以下原则：

1. 自由布局默认不自动填补源项目留下的远距离空白，避免改变用户刻意摆放的位置。
2. 仅当新紧凑堆叠、展开网格或提取后的独立节点与邻近节点发生明显碰撞时触发避让。
3. 受影响范围以操作对象外接矩形向外扩展 **48–80 画布像素**计算。
4. 优先沿最短位移方向推开邻居，并保持至少 **20–28 画布像素**间距。
5. 不移动锁定节点、正在编辑节点和不在影响范围内的节点。
6. 若未来存在自动整理/网格模式，该模式可额外执行源空位补位；自由布局模式保持上述最小干预策略。

### FR-12 成功和错误反馈

1. 创建成功：顶部居中显示“已创建堆叠”。
2. 追加成功：显示“已加入堆叠”，连续操作合并提示。
3. 提取成功通常不弹提示，以空间动画作为主要反馈。
4. 不可投放目标：目标轻微左右晃动或边框转为禁用色，不显示阻塞式弹窗。
5. 提示动画：
   - 淡入并下移 `8–12 px`，`160–220 ms`；
   - 停留 `1000–1400 ms`；
   - 淡出并上移 `4–8 px`，`180–240 ms`。

## 7. 动画编排

### 7.1 动画总原则

1. 位移优先使用 `translate` 或等效高性能路径；最终坐标必须与持久状态一致。
2. 动画不改变用户当前缩放比例和视口位置。
3. 拖动跟手阶段不使用补间追赶指针；吸附、释放、补位阶段再使用补间。
4. 同一对象同一时刻只允许一个主要位置动画，新的指针操作应终止旧动画并从当前视觉位置接管。
5. 阴影、缩放和透明度用于强调状态，幅度克制，不做明显弹跳。
6. 周边重排采用 FLIP：记录旧位置 → 提交新布局 → 从旧视觉位置补间到新位置。

### 7.2 动画时长与缓动

| 动作 | 时长 | 推荐缓动 | 视觉细节 |
|---|---:|---|---|
| 按下/抓起 | 80–140 ms | `power2.out` | 缩放至 1.02、阴影增强、升层 |
| 目标激活 | 120–180 ms | `power2.out` | 目标缩放至 1.015、轮廓增强 |
| 磁性吸附预览 | 120–180 ms | `power2.inOut` | 被拖项最多向目标中心偏移 8–16 px |
| 创建/合并 | 200–350 ms | `power3.inOut` | 来源进入锚点，目标抬升，层边出现 |
| 追加成员 | 180–300 ms | `power3.out` | 新成员沿拖入方向进入堆叠 |
| 展开 | 300–500 ms | `power3.out` | 从锚点向网格辐射，轻微 stagger |
| 收拢 | 220–380 ms | `power2.inOut` | 沿反向路径吸回，外侧先动 |
| 成员提取抓起 | 80–140 ms | `power2.out` | 提取成员升层，原槽保留 |
| 提取落下 | 160–260 ms | `power3.out` | 微小减速，不做明显回弹 |
| 成员补位 | 220–360 ms | `power3.inOut` | FLIP 填槽，数量同步更新 |
| 邻近节点重排 | 250–450 ms | `power3.inOut` | 仅影响局部邻居 |
| 成功提示 | 160–220 ms 入场 | `power2.out` | 顶部淡入并轻微下移 |

### 7.3 创建堆叠时间线

以释放时刻 `T0` 为起点：

1. `T0–T0+60 ms`：锁定目标；目标轮廓达到最强；被拖项停止自由跟手。
2. `T0+20–220 ms`：被拖项向锚点移动并缩放到 `0.985–1.0`。
3. `T0+80–260 ms`：目标项抬升约 `4–8 px` 后回落，后方层边逐层出现。
4. `T0+180–300 ms`：数量标签由无到有，淡入并缩放 `0.92 → 1`。
5. `T0+220–450 ms`：邻近节点按需局部重排。
6. `T0+260 ms` 左右：顶部成功提示开始入场；提示不阻塞后续拖拽。

### 7.4 展开时间线

1. 标题/数量先稳定在锚点，作为视觉参照。
2. 顶层成员在 `0 ms` 开始移动，其余成员以 **18–35 ms** 间隔错峰启动。
3. 每个成员从紧凑层偏移和旋转状态，过渡到网格槽位的 `x/y/rotation=0/scale=1`。
4. 远离锚点的成员允许比近处成员晚 `20–60 ms` 到达，形成向外铺开的方向感。
5. 成员阴影从紧凑层叠阴影过渡为普通卡片阴影；透明度不低于 `0.88`，避免像凭空出现。
6. 动画完成前约最后 `80 ms` 即可开放悬停反馈，但拖拽必须在主位移动画完成或被明确接管后启动。

### 7.5 收拢时间线

1. 外围成员先向锚点移动，中心附近成员晚 **15–30 ms** 启动。
2. 位移过程中逐渐恢复各自的层边偏移、轻微旋转和 z-index 顺序。
3. 数量标签始终保持可见，不随成员一起缩回。
4. 最后一个成员到达后再解除展开态交互层，避免下方节点提前接收点击。

### 7.6 提取与补位时间线

1. 超过拖拽阈值：提取成员在 `80–140 ms` 内升层；原槽生成无边框占位。
2. 拖动中：其他成员保持原槽；数量仅显示预览，不提交。
3. 成功释放：提取成员在 `160–260 ms` 内落下。
4. 释放后 `40–80 ms`：原堆叠剩余成员开始补位。
5. 补位持续 `220–360 ms`；距离空槽最近、排序最靠前的后续成员依次移动。
6. 数量标签在补位动画进行到约 **50%** 时切换，使用 `scale 0.92 → 1` 和淡入过渡。
7. 若触发单成员自动解散，层边和数量在最后成员回到锚点后的 `140–220 ms` 内淡出。

## 8. 交互状态机

| 状态 | 进入条件 | 允许操作 | 退出条件 |
|---|---|---|---|
| `idle` | 无活动交互 | 选择、按下、打开 | 指针按下进入 `pressed` |
| `pressed` | 按下但未过阈值 | 松开作为点击 | 超过 4 px 进入拖拽；取消回 `idle` |
| `dragging-item` | 拖动独立项目 | 跟手、检测目标 | 命中目标进入 `over-stack-target`；释放到空白完成移动 |
| `dragging-stack` | 从外壳拖动堆叠 | 整体跟手 | 释放后进入 `layout-reflow` 或紧凑/展开态 |
| `over-stack-target` | 满足激活条件 | 吸附预览、取消激活 | 释放进入 `stack-merging`；移出回拖动态 |
| `stack-merging` | 在目标上释放 | 播放合并动画 | 完成进入 `stack-compact` |
| `stack-compact` | 堆叠收拢完成 | 选中、整体拖动、展开 | 展开进入 `stack-expanding` |
| `stack-expanding` | 触发展开 | 播放成员外移动画 | 完成进入 `stack-expanded`；取消则反向收拢 |
| `stack-expanded` | 展开完成 | 打开成员、拖成员、拖外壳 | 提取进入 `extracting-item`；离开进入 `stack-collapsing` |
| `extracting-item` | 拖动具体成员 | 跟手、返回原堆、投放文件夹 | 外部释放进入 `layout-reflow`；返回原堆回 `stack-expanded` |
| `layout-reflow` | 成员关系或落点已提交 | 补位、邻居避让 | 动画结束进入对应稳定态 |
| `stack-collapsing` | 离开、Esc、点击空白 | 播放反向动画 | 完成进入 `stack-compact`；指针返回可反转展开 |

### 8.1 中断和取消

1. `pointercancel`：恢复本次手势开始前的成员关系和视觉位置，不写历史。
2. 拖动过程中按 `Esc`：取消当前拖动并回到手势开始前状态。
3. 窗口失焦：等同 `pointercancel`，避免卡在拖动态。
4. 新拖拽开始时若目标正在展开/收拢，先停止旧补间，从当前视觉位置无缝接管。
5. 数据保存失败：保留本地 UI 状态并显示非阻塞错误；不得立即把视觉状态跳回旧位置。

## 9. 数据与状态要求

### 9.1 持久状态

建议保留现有 `CanvasNode.stackId` 作为成员关系键，并增加明确的堆叠元数据，以避免标题、锚点和顺序依赖某个“顶层成员”：

```ts
interface CanvasStack {
  id: string;
  title: string;
  anchorX: number;
  anchorY: number;
  memberOrder: string[];
  createdAt: number;
  updatedAt: number;
}
```

约束：

1. `memberOrder` 只包含 `stackId === stack.id` 的根级节点。
2. 一个节点最多属于一个堆叠；加入堆叠时必须 `parentId === null`。
3. 节点移入文件夹时自动退出堆叠。
4. 成员少于两个时自动删除 `CanvasStack`。
5. 堆叠移动和成员关系变化需要原子保存，避免崩溃后成员散落或重复。

如果本期不引入独立 `CanvasStack` 表，至少需要在工作区快照中维护等价的 `stackMetaById`，不能仅靠最高 `zIndex` 成员推断标题和锚点。

### 9.2 临时 UI 状态

以下内容不持久化：

- 当前交互状态；
- 当前展开的堆叠 ID；
- 展开网格的临时槽位；
- 当前投放目标；
- 提取空槽；
- 悬停和离开计时器；
- 正在播放的动画引用；
- 局部重排预览。

### 9.3 历史记录粒度

以下每项各生成一条历史记录：

1. 创建堆叠；
2. 向堆叠追加成员；
3. 移动整个堆叠；
4. 成功提取成员；
5. 从堆叠成员直接移入文件夹；
6. 显式解散堆叠。

展开、收拢、悬停、取消提取和投放预览不进入历史。

## 10. 排序、层级和坐标规则

1. 新建堆叠的成员顺序：目标成员在前，被拖成员在后。
2. 追加成员默认放到 `memberOrder` 末尾。
3. 展开网格按 `memberOrder` 从左到右、从上到下排列。
4. 提取取消恢复原索引；提取成功后其后的成员顺序前移。
5. 紧凑态顶层默认显示最后加入或最近操作的成员，但这不改变 `memberOrder`。
6. 整体堆叠的 z-index 高于普通未选中节点；展开成员的交互层级高于紧凑堆叠。
7. 提取成员始终处于当前画布交互最高层。
8. 视口缩放不改变屏幕级拖拽阈值和视觉阴影强度；画布间距和坐标按世界坐标计算。

## 11. 边界情况

1. **拖回原堆叠**：取消提取，恢复原顺序，不记录历史。
2. **目标在动画中**：等待目标进入可接管帧，或从当前视觉状态平滑转入吸附；不得瞬移。
3. **成员正在编辑**：编辑控件内拖动文本、滚动或选择内容不得触发提取。
4. **不同尺寸成员**：网格以行列最大尺寸计算，不拉伸卡片。
5. **超出视口**：展开网格整体偏移到可见方向，但锚点仍用连线/标题位置保持来源关系。
6. **大量成员**：最多 5 列，继续增加行；动画 stagger 总延迟封顶约 240 ms，避免成员越多等待越久。
7. **删除成员**：删除后按提取后的补位规则处理；只剩一个成员时自动解散。
8. **删除整个堆叠**：选中堆叠外壳删除时，应明确删除所有成员或先二次确认；本期默认沿用“删除选中节点”的确认策略。
9. **缩放/平移画布**：成员拖拽期间禁止同时平移画布；靠近视口边缘的自动平移若后续实现，必须独立立项。
10. **拖到自身成员上**：视为回到原堆叠，不创建新的堆叠关系。
11. **多选拖拽**：多选整体移动保持现有行为；本期不允许多选集合直接追加到堆叠。
12. **文件夹子项**：文件夹内部子项必须先移出文件夹成为根节点，或通过明确的“移到画布并加入堆叠”操作处理。

## 12. 无障碍与减少动态效果

### 12.1 键盘

1. `Tab` 聚焦堆叠外壳。
2. `Enter` / `Space` 展开或收拢。
3. 展开后方向键在成员网格中移动焦点。
4. `Esc` 取消拖动或收拢堆叠。
5. 为堆叠提供可读名称，例如“未命名堆叠，9 个项目，已收拢”。
6. 数量变化通过 `aria-live="polite"` 低优先级播报。

### 12.2 减少动态效果

当系统启用 `prefers-reduced-motion: reduce`：

1. 取消大范围飞行动画和旋转变化。
2. 抓起、展开、收拢、补位缩短为 **60–100 ms** 的透明度和轻微位移过渡。
3. 不使用回弹、晃动和错峰延迟。
4. 功能顺序、目标提示和最终布局保持不变。

## 13. 验收标准

### AC-01 创建堆叠

- 将 A 拖到 B 的中心有效区域并释放，A、B 形成一个堆叠。
- 合并过程可连续看见 A 向 B 锚点移动。
- 紧凑态显示正确数量 `2`，顶部出现成功提示。
- 一次撤销后 A、B 回到各自原位置。

### AC-02 目标稳定性

- 仅擦过目标边缘不会立即激活。
- 指针在目标边缘轻微抖动时，目标不会连续闪烁开关。
- 离开目标后吸附和高亮能在短延迟后平滑取消。

### AC-03 追加成员

- 将 C 拖到包含 A、B 的堆叠上，数量从 2 变为 3。
- C 沿拖入方向进入堆叠，不瞬间消失。
- A、B 的成员关系和顺序保持稳定。

### AC-04 展开与收拢

- 9 个成员展开为 3×3 规则网格。
- 每个成员都能看出从堆叠锚点移动到对应槽位。
- 指针穿过成员间隙不会立即触发收拢。
- 离开联合热区后，成员沿反向路径回到紧凑态，收拢比展开略快。

### AC-05 整体移动

- 拖动紧凑外壳时，所有成员同步移动且相对层边不变。
- 拖动展开态标题时，整个网格同步平移。
- 释放后只有一条历史记录，撤销可恢复整个堆叠位置。

### AC-06 提取成员

- 从展开网格拖出一个成员时，原槽保持空位，其他成员不提前跳动。
- 在外部释放后，该成员成为独立节点，数量减一。
- 剩余成员使用连续补位动画填槽。
- 将成员拖回堆叠区域释放时，恢复原槽且不产生历史记录。

### AC-07 自动解散

- 二成员堆叠提取一个成员后，剩余成员自动解除堆叠。
- 层边和数量标签平滑淡出，剩余成员停留在锚点。
- 撤销可恢复原二成员堆叠。

### AC-08 文件夹兼容

- 将节点拖到文件夹时仍进入文件夹，不创建堆叠。
- 堆叠展开不打开 `FolderFocus`。
- 从堆叠提取成员并投放到文件夹后，成员退出堆叠并成为该文件夹子项。

### AC-09 性能与视觉稳定性

- 拖动跟手期间没有明显回跳、旧位置闪现或全画布闪烁。
- 只有被拖对象、目标和局部受影响节点更新。
- 9 个成员的展开、收拢、提取在常规桌面设备上保持流畅。
- 动画结束后的 DOM/渲染坐标与持久状态一致。

## 14. 推荐实施拆分

1. **数据层**：堆叠元数据、成员顺序、原子持久化、历史记录。
2. **目标检测层**：普通节点目标、已有堆叠目标、文件夹优先级、滞回和停留时间。
3. **紧凑态组件**：层边、数量、标题、外壳拖动。
4. **展开态布局**：自适应网格、联合热区、视口边界修正。
5. **动画控制器**：创建、追加、展开、收拢、提取和 FLIP 补位。
6. **拖拽状态机**：独立节点、整堆、展开成员三类拖拽互斥。
7. **局部碰撞重排**：邻居查询、最小位移、预览和提交。
8. **无障碍/减少动态效果**：键盘导航、语义播报和降级动画。
9. **自动化测试**：状态转换、历史记录、目标判定、单成员解散。
10. **视觉回归测试**：2、3、9、20 成员以及不同尺寸卡片场景。

## 15. 最终体验定义

完成后的堆叠不是一个“点击后打开的容器”，而是画布上的可触摸对象：项目可以被吸入、从同一锚点铺开、随整个堆叠移动，再从网格中被拿出。动画不是装饰，而是成员关系变化的解释层。所有实现选择都应优先保证空间连续性、目标确定性和可撤销性。
